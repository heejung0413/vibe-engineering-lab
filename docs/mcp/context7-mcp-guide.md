# Context7 MCP 서버 가이드

## 개요

Context7는 Model Context Protocol(MCP)를 통해 공식 라이브러리 문서, 코드 예제, 베스트 프랙티스를 제공하는 MCP 서버입니다. 외부 라이브러리나 프레임워크를 사용할 때 정확한 문서를 참조하여 구현할 수 있도록 지원합니다.

## 주요 기능

### 1. 라이브러리 문서 제공
- 공식 라이브러리 문서와 API 레퍼런스 조회
- 프레임워크별 베스트 프랙티스
- 코드 예제와 구현 패턴

### 2. 로컬라이제이션 지원
- 다국어 문서 표준 제공
- 언어별 커뮤니케이션 규범
- 문화적 맥락을 고려한 콘텐츠 적응

## 활성화 패턴

### 자동 활성화
다음 상황에서 자동으로 활성화됩니다:

- **외부 라이브러리 임포트 감지**
  ```javascript
  import React from 'react';
  import { useQuery } from '@tanstack/react-query';
  ```

- **프레임워크 관련 질문**
  - "Next.js에서 API 라우트를 어떻게 만들어?"
  - "Vue 3의 Composition API 사용법은?"

- **Scribe 페르소나 활성화 시**
  - 문서 작성 작업
  - 로컬라이제이션 작업

### 수동 활성화
다음 플래그를 사용하여 명시적으로 활성화할 수 있습니다:

```bash
--c7
--context7
```

## 워크플로우

### 1. 라이브러리 감지
```yaml
작업: 코드에서 라이브러리 참조 스캔
대상:
  - import/require 문
  - package.json 의존성
  - 프레임워크 키워드
```

### 2. ID 해석
```yaml
도구: resolve-library-id
목적: Context7 호환 라이브러리 ID 찾기
예시:
  - "react" → "react@18"
  - "next.js" → "nextjs@14"
```

### 3. 문서 검색
```yaml
도구: get-library-docs
매개변수:
  - library_id: 해석된 라이브러리 ID
  - topic: 특정 주제 (선택사항)
결과: 공식 문서 내용
```

### 4. 패턴 추출
```yaml
작업: 관련 코드 패턴과 구현 예제 추출
검증:
  - 공식 문서와의 일치성
  - 버전 호환성
```

### 5. 구현
```yaml
작업: 추출된 패턴을 코드에 적용
원칙:
  - 적절한 출처 표시
  - 버전 호환성 확인
```

### 6. 검증
```yaml
작업: 구현이 공식 문서와 일치하는지 확인
도구: 린터, 타입 체커
```

### 7. 캐싱
```yaml
작업: 성공적인 패턴을 세션 재사용을 위해 저장
최적화: 2-5K 토큰/쿼리 절약
```

## 통합 명령어

Context7은 다음 명령어들과 통합되어 작동합니다:

| 명령어 | 사용 목적 | Context7 역할 |
|--------|-----------|---------------|
| `/build` | 프로젝트 빌드 | 프레임워크 패턴 제공 |
| `/analyze` | 코드 분석 | 베스트 프랙티스 검증 |
| `/improve` | 코드 개선 | 개선 패턴 제공 |
| `/design` | 시스템 설계 | 아키텍처 패턴 |
| `/document` | 문서 작성 | 문서화 표준 |
| `/explain` | 개념 설명 | 공식 문서 참조 |
| `/git` | Git 작업 | 커밋 메시지 패턴 |

## 에러 복구

### 라이브러리를 찾을 수 없음
```yaml
문제: Context7에서 라이브러리를 찾을 수 없음
해결책:
  1. WebSearch로 대안 검색
  2. 수동 구현
  3. 제한 사항 명시
```

### 문서 타임아웃
```yaml
문제: 문서 검색 시간 초과
해결책:
  1. 캐시된 지식 사용
  2. 제한 사항 명시
  3. 대체 접근법 제안
```

### 잘못된 라이브러리 ID
```yaml
문제: 라이브러리 ID 해석 실패
해결책:
  1. 더 넓은 검색어로 재시도
  2. WebSearch로 폴백
  3. 수동 확인 요청
```

### 버전 불일치
```yaml
문제: 프로젝트와 문서의 버전 불일치
해결책:
  1. 호환 버전 찾기
  2. 업그레이드 경로 제안
  3. 버전별 차이점 명시
```

### 서버 사용 불가
```yaml
문제: Context7 서버 연결 실패
해결책:
  1. 백업 Context7 인스턴스 활성화
  2. 점진적 성능 저하
  3. 캐시된 정보 활용
```

## 사용 예시

### React 컴포넌트 구현
```bash
# 자동으로 Context7이 활성화되어 React 패턴 제공
/implement "사용자 프로필 카드 컴포넌트"

# Context7이 다음을 제공:
# - React 18의 최신 패턴
# - 접근성 베스트 프랙티스
# - 컴포넌트 구조 가이드
```

### API 엔드포인트 설계
```bash
# Next.js API 라우트 패턴 조회
/build --api "RESTful 사용자 엔드포인트"

# Context7이 제공:
# - Next.js 13+ App Router 패턴
# - 에러 처리 방법
# - 타입 안전성 구현
```

### 문서 작성
```bash
# 다국어 문서 표준 제공
/document --persona-scribe=ko "API 사용 가이드"

# Context7이 제공:
# - 한국어 기술 문서 작성 표준
# - 코드 예제 포맷팅
# - 문화적 맥락 고려
```

# 일반적인 조회
get-library-docs(library_id="react")

# 특정 토픽 조회 (더 효율적)
get-library-docs(library_id="react", topic="hooks")

## MCP 서버 선호도

### Context7과 함께 사용하면 좋은 서버

**Sequential (복잡한 분석)**
- 용도: 다단계 문제 해결
- 조합: Context7(문서) + Sequential(분석)

**Magic (UI 컴포넌트)**
- 용도: 현대적인 UI 생성
- 조합: Context7(패턴) + Magic(생성)

### Context7 단독 사용이 적합한 경우

- 라이브러리 API 조회
- 프레임워크 베스트 프랙티스 확인
- 문서화 표준 참조
- 로컬라이제이션 가이드

## 퍼포먼스 메트릭

### 응답 시간
- 라이브러리 ID 해석: ~100ms
- 문서 검색: ~500ms
- 캐시 히트: ~10ms

### 토큰 효율성
- 직접 검색 대비: 40-60% 토큰 절약
- 캐시 활용 시: 80-90% 토큰 절약

### 정확도
- 공식 문서 일치율: 98%+
- 버전 호환성 검증: 95%+
